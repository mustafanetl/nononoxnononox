Fix parser same-line fences, homepage fresh-chat, plane flight map animation

Parser fix (blocks not rendering)
- The new planParser required a newline between the fence name and the
  JSON content. Some AI responses emit the JSON on the same line as the
  fence (e.g. ```itinerary[{...}]```). Added same-line detection: if
  there's content between the fence name and the first newline that
  starts with [ or {, treat it as the raw block content. This restores
  itinerary/activities/hotels rendering that broke after the parser
  rewrite.

Homepage → fresh chat
- When the user types on the homepage search box and lands on /chat?q=...,
  always start a new conversation. Previously if they had an old chat in
  localStorage, the ?q= param was silently ignored (messages.length > 0
  guard). Now clearChat() fires first, then sendMessage(q) runs in a
  microtask so the state flush lands.

Plane flight map animation (PlanCraftingMap rewrite)
- Full-bleed animated world map with a plane flying from origin city to
  destination city along a smooth quadratic bezier arc.
- The trail is drawn behind the plane as it moves, revealed via
  stroke-dashoffset tied to crafting progress — so the line grows
  smoothly from 0% to 100%.
- Origin pin with label, destination pin with double-pulse rings, plane
  glyph with glow that rotates to follow the tangent of the arc.
- Ambient city photo behind the map (blurred, ken-burns zoom) so the
  canvas feels like it's about a real place even before venues stream.
- Dot grid + white wash for depth without obscuring the flight path.
- Activity stream list below with shimmer placeholders that animate in
  as venue names arrive.

Pass itineraryVenuePhotos to TripDetail
- TripSummaryCard now accepts and stores itineraryVenuePhotos in
  sessionStorage so TripDetail has venue photos on first paint without
  waiting for a re-enrichment round-trip.
